# מבט

דוחות חודשיים אוטומטיים ללקוחות של משרדי רו"ח ויועצי מס. המערכת קולטת ייצוא
"מבנה אחיד" (OPENFRMT) מתוכנת הנהלת החשבונות ומפיקה לכל לקוח דוח חודשי בעברית:
הכנסות, הוצאות, רווח תפעולי, השוואה לחודשים קודמים וחריגות.

הכלי מיועד לרו"ח. הוא לא שולח דבר ללקוח הקצה; כל דוח הוא טיוטה עד שרו"ח מסמן
אותו "נסקר", וההורדה ידנית.

## עקרונות

- **כל מספר מחושב בקוד.** אין מודל שפה בשלב הזה. הניסוח נעשה בתבניות קבועות,
  וסכומים מוחזקים כאגורות שלמות (בלי float).
- **אי-התאמה עוצרת.** אם הקובץ לא תואם את הספירות שב-`INI.TXT`, או שיש חשבון
  פעיל בלי סיווג, לא מופק דוח.
- **הנתונים נשארים במחשב.** הדשבורד מאזין על `127.0.0.1` בלבד, הדוח לא טוען
  שום משאב מהרשת, ונתוני לקוחות לא נכנסים ל-git (`data/real/`, `output/`).

## התקנה

דרוש Python 3.10 ומעלה.

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/python -m playwright install chromium   # נדרש להפקת PDF
```

## שימוש

```bash
# דוח לחודש האחרון של לקוח הדמה (HTML + PDF בתיקייה output/)
.venv/bin/mabat run data/sample

# חודש מסוים, או כל החודשים שבייצוא
.venv/bin/mabat run data/sample --month 2026-05
.venv/bin/mabat run data/sample --all-months

# תיקיית שורש עם כמה לקוחות: כל תיקייה שיש בה INI.TXT מעובדת בנפרד
.venv/bin/mabat run /path/to/OPENFRMT

# דשבורד לסקירה: http://127.0.0.1:8000
.venv/bin/mabat serve
```

`mabat run` מחזיר קוד יציאה 1 אם תיק כלשהו נכשל בוולידציה (שאר התיקים מופקים),
ו-2 אם לא נמצא אף ייצוא.

בדשבורד מעלים תיקייה או את שני הקבצים, רואים את הדוחות עם סטטוס
"מוכן" / "דורש בדיקה", פותחים דוח, מסמנים "נסקר" ומורידים HTML או PDF. קובצי
המקור שהועלו נמחקים בסוף הבקשה; נשמרים רק הנתונים המחושבים של הדוח.

דוח מסומן **"דורש בדיקה"** אם יש בו חריגה אדומה או כתומה, או הערה על איכות
הנתונים. אחרת הוא **"מוכן"**.

## הגדרות (`config/`)

| קובץ | מה הוא קובע |
|---|---|
| `fieldmap.yaml` | מיקומי השדות בכל סוג רשומה, לפי המפרט הרשמי (מספר שדה ועמודות) |
| `classification.yaml` | אילו חשבונות הם הכנסה, הוצאה או מאזניים, ולפי איזה תאריך משייכים תנועה לחודש |
| `thresholds.yaml` | ספי החריגות |

המפרט הרשמי של רשות המסים (מהדורה 1.31) שמור ב-`docs/spec/`.

## מעבר לקובץ אמיתי

`classification.yaml` מתאים לנתוני הדמה בלבד. כשמגיע ייצוא אמיתי:

1. שמים אותו תחת `data/real/` (התיקייה מחוץ ל-git) ומריצים `mabat run data/real`.
2. אם הפרסר עוצר על אורך רשומה או על ספירה, משווים את השורה למפרט ומתקנים את
   `fieldmap.yaml` רק אם המפרט עצמו תומך בתיקון.
3. הריצה תעצור עם רשימת החשבונות שאין להם סיווג. כותבים להם כללים
   ב-`classification.yaml` לפי קוד מאזן בוחן (שדה 1405) או קוד 6111 (שדה 1417).
4. בודקים מול מאזן בוחן מהתוכנה שסכומי ההכנסות וההוצאות לחודש תואמים.

עדיין פתוח מול משרד הפיילוט:

- לפי איזה תאריך המשרד משייך תנועה לחודש. ברירת המחדל כאן היא שדה "תאריך"
  (1362); אפשר להחליף ל"תאריך ערך" (1363) ב-`classification.yaml`.
- האם פקודות סגירת שנה מופיעות בייצוא ומאפסות חשבונות תוצאתיים בדצמבר.

## מבנה הקוד

```
mabat/
  ingest/      זיהוי קידוד, פענוח לפי fieldmap, ולידציה מול INI.TXT
  normalize/   סיווג חשבונות וצבירה ל-{account, category, type, month, amount}
  compute/     רווח והפסד והשוואה חודשית
  anomalies/   חוקי החריגות
  narrate/     ניסוח הממצאים + שומר שמונע מספר שלא חושב
  report/      תבנית HTML, גרף SVG, ייצוא PDF
  store/       SQLite: הדוחות ומצב הסקירה
  web/         הדשבורד
  pipeline.py  חיבור השלבים
  cli.py       שורת הפקודה
```

## בדיקות

```bash
.venv/bin/python -m pytest
```

נתוני הדמה נוצרים באופן דטרמיניסטי (`mabat sample` או `tools/generate_sample.py`),
והבדיקות נשענות על הסכומים הידועים שלהם.
